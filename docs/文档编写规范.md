# 文档编写规范

## 适用范围

本规范适用于前端与后端对接时编写的功能文档。团队无产品经理角色，前端负责输出此类文档。

## 文档定位

**前后端接口对接文档**——不是纯 PRD，也不是纯技术方案，而是两者的结合：

- 功能说明（做什么）+ 接口契约（怎么对接）写在同一份文档里
- 后端拿到后能直接开工，不需要额外沟通

## 文档结构

每份功能文档应包含以下部分：

### 1. 基本信息（表格）

| 字段 | 说明 |
| --- | --- |
| 页面 | 页面名称 |
| 路由 | 前端路由路径 |
| 涉及表 | 对应的数据库表名 |
| 更新日期 | 最后更新日期 |
| 前端状态 | 已完成 / 占位 / 待接口对接 |

### 2. 功能说明

- 用自然语言描述页面做什么
- 列出用户操作流程（1、2、3 步骤）
- 不需要贴 UI 截图，文字描述清楚即可

### 3. 需要的接口

每个接口包含：

- **接口名称**（如"AI 生成分镜脚本"）
- **前端触发时机**（哪个按钮 / 哪个页面事件触发）
- **HTTP 方法 + 路径**（如 `POST /api/v1/projects/:id/storyboards/generate`）
- **Request JSON 示例**
- **Response JSON 示例**（标注对应的数据库表）
- **补充说明**（异步任务需要轮询、枚举值范围等）

### 4. 当前状态（可选）

说明前端实现进度，以及临时方案（如"暂存 localStorage，接口就绪后替换"）。

## 编写原则

1. **接口字段以数据库设计为准**——字段名、枚举值直接引用数据库设计文档，不要自己另起一套命名。
2. **不重复写数据库设计**——只引用表名和关键字段，不抄建表 SQL。数据库设计文档由后端维护。
3. **争议点在文档留痕**——接口是轮询还是 WebSocket、批量生成是同步还是异步等约定，写在文档里，不要只口头沟通。
4. **一个功能模块一个 md**——按页面或步骤拆分，不要把所有内容堆在一个文件里。
5. **保持可维护**——后端实现时如果调整了字段，直接在这份文档上改，保持单一信息源。

## 目录结构

```
docs/
├── README.md                  # 文档总索引
├── ROADMAP.md                 # 阶段路线图
├── 文档编写规范.md             # 本文件
├── 工作流/                    # 按功能模块分目录
│   ├── README.md              # 模块总览 + 接口汇总表
│   ├── 模式选择.md
│   ├── step-1-项目全局参数.md
│   ├── step-2-故事设定.md
│   └── ...
└── feishu/                    # 飞书同步文档（历史）
```

## 接口汇总表模板

每个功能模块的 README 中应包含接口汇总表：

```markdown
| 方法 | 路径 | 说明 | 涉及表 | 状态 |
| --- | --- | --- | --- | --- |
| POST | `/api/v1/xxx` | 创建xxx | `table_name` | 未开发 |
| GET | `/api/v1/xxx` | 获取xxx | `table_name` | 已联调 |
```

状态枚举：`未开发` / `开发中` / `已联调` / `已上线`
